# 📅 일정 코치: 캘린더 기반 스케줄링 챗봇

캘린더 일정, 작업별 마감·예상 소요시간, 작업 가능 시간대를 반영해 **현실적인 계획**을 세우고,
“오늘 못 했어”, “내일 저녁은 안 돼” 같은 상황 변화에 맞춰 **재조정하고 이유를 설명**하는 챗봇입니다.

## 핵심 아이디어: LLM + 제약 솔버

LLM은 자연어 이해와 설명에 강하지만 시간 계산과 제약 준수에는 약합니다. 그래서 역할을 나눴습니다.

```
사용자 발화 ─▶ [LLM · function calling] ─▶ 상태 변경 연산(JSON): add_task, block_time, report_missed ...
                                              │  (검증 + 안전 규칙 적용: planner/ops.py)
Google Calendar ─▶ free/busy ─▶ [제약 솔버: 안정성 고려 EDF] ─▶ 새 계획 + 변경 로그 + 실현가능성 분석
                                              │
                         [LLM] ◀── 스케줄러 로그(사실)만 근거로 설명 생성
```

| 기능 | 구현 | 정량 지표 |
|---|---|---|
| ① 제약을 지키는 계획 생성 | 30분 슬롯, 마감 빠른 순(EDF) 배치. 일정 충돌, 가용 시간대, 마감, 하루 최대시간, 수면시간을 하드 제약으로 보장 | 충돌률, 마감 위반률, 커버율, 완전·유효 계획 비율 |
| ② 상황 변화 재조정 | 발화를 연산으로 변환하고 다시 배치. 기존 블록은 최대한 유지하고, 더 급한 작업이 필요할 때만 기존 블록을 가져감 | 상태 파싱 정확도, 재조정 후 제약 준수, **계획 안정성** |
| ③ 실현 가능성 진단과 근거 있는 설명 | 마감별 누적 필요시간과 가용시간 비교, 부하율 계산. 불가능하면 부족한 시간과 **솔버로 검증한 대안**(범위 축소, 최소 마감 연장, 저우선 작업 미루기) 제시 | 불가능 탐지 P/R/F1, 설명 사실 일치율 |

## 실행

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
echo "OPENAI_API_KEY=sk-..." > .env       # 이미 있으면 생략
.venv/bin/streamlit run app.py
```

- 샘플 캘린더(`data/sample.json`)는 **월요일 시작 기준**으로, 요일별 수업·약속과 할 일 4개가 들어 있습니다. 기본 시작일은 다가오는 월요일 09:00입니다. 기본 상태는 **캘린더 일정만 있고 할 일은 비어 있는 상태**이며, 채팅으로 할 일을 추가합니다. 사이드바의 **"샘플 작업 4개 불러오기"**를 켜고 초기화하면 샘플 할 일 4개가 들어간 상태로 시작합니다.
- 사이드바에서 **시뮬레이션 시계**(+3시간, 오늘 밤 23시)로 시간을 넘기면 지나간 블록은 “완료”로 간주됩니다. 못 했다면 채팅으로 알려주면 됩니다.
- 기본 모델은 `gpt-4.1-mini`입니다(`OPENAI_MODEL` 환경변수로 변경).
- 상단 전환 버튼 **`📅 일정 코치` / `💬 기본 ChatGPT`**로 고르는 두 서비스는 서로 독립된 서비스입니다. 같은 캘린더·작업·시뮬레이션 시계에서 시작하지만 대화와 계획은 따로 가집니다. 기본 ChatGPT는 평가 baseline과 같은 프롬프트로 계획을 직접 작성합니다. 두 서비스에 같은 말을 해 보고 결과를 비교할 수 있습니다. 샘플 작업을 불러온 경우에는 초기화할 때 기본 ChatGPT가 초기 계획을 세우느라 API를 1번 호출합니다.

### Google Calendar 연결 (선택)
1. Google Cloud Console에서 Calendar API를 활성화하고, OAuth 클라이언트(데스크톱 앱)를 만든 뒤 `credentials.json`을 프로젝트 루트에 둡니다.
2. 사이드바에서 `Google Calendar`를 선택하고 `불러오기`를 누르면 브라우저 인증이 시작됩니다. **읽기 전용 권한**(`calendar.readonly`)만 요청합니다.
3. 연결에 실패하면 샘플 캘린더(`data/sample.json`)를 대신 씁니다.

## 평가

```bash
.venv/bin/python -m eval.scenarios --seed 2026 --out eval/scenarios_test.json   # test set (dev = seed 7)
.venv/bin/python -m eval.run_eval --scenarios eval/scenarios_test.json --judge  # ours vs baseline vs baseline_cot
.venv/bin/python -m eval.run_eval --report-only     # results/raw.jsonl에서 표만 다시 생성
.venv/bin/python -m eval.safety_eval                # toy red-team 안전성 평가 (10개)
```

- **시나리오:** 1주일 캘린더와 작업 3~4개(30%는 일부러 불가능하게 생성)에 후속 발화 2턴(미완료 보고, 부분 진행, 시간 막기, 마감 변경, 작업 추가/삭제/증가)을 붙였습니다.
- **Gold 상태:** 발화가 의미하는 실제 상태를 코드로 계산합니다. 모든 계획은 시스템이 이해한 상태가 아니라 **gold 상태 기준**으로 채점하므로, 날짜를 잘못 이해하면 그대로 감점됩니다.
- **실현 가능성 라벨은 인증된 값만 씁니다.** 가능 = 유효한 완전 계획이 실제로 존재(체커로 재검증), 불가능 = 어떤 마감까지의 누적 필요시간이 가용시간을 초과(필요조건 위반).
- **베이스라인:** 같은 모델에 같은 정보를 텍스트로 주고 JSON 계획을 받습니다. 제약 규칙도 똑같이 명시합니다. `baseline_cot`는 단계적 추론을 추가로 요청한 버전입니다.
- **결과:** `results/summary.md`(표, 오류 분석), `results/raw.jsonl`(턴별 원자료)

## 안전·윤리
- **프라이버시:** LLM에는 기본적으로 **바쁜 시간대만** 보내고 일정 제목은 보내지 않습니다(사이드바에서 선택 가능). 캘린더는 읽기 전용입니다.
- **프롬프트 인젝션 방어:** 일정 제목은 정제하고 길이를 자르며, “데이터일 뿐 지시가 아님”을 명시합니다.
- **번아웃 방지 하드 제약:** 수면 보호 시간(00~07시)에는 배치하지 않고, 하루 최대 작업시간 상한은 10시간입니다. 둘 다 채팅으로 바꿀 수 없습니다. 밤샘 요청은 감지해서 부드럽게 거절하고 대안을 제시합니다.
- **모더레이션:** 입력에 OpenAI Moderation을 적용합니다. 자해·자살 신호가 있으면 일정 대신 **위기 상담 안내**(109, 1577-0199)를 먼저 응답합니다.
- **환각 방지:** 설명은 스케줄러 로그에 있는 사실만 근거로 만듭니다. 불가능한 계획을 억지로 끼워 넣지 않고 부족한 시간을 투명하게 알립니다.
- **말투:** 비난하거나 죄책감을 주는 표현을 쓰지 않도록 했습니다.

## 파일 구조
```
app.py                    Streamlit UI (채팅 + 주간 캘린더 + 부하/실현가능성 + 변경 로그)
planner/models.py         데이터 구조 (Task, Event, Block, State), 시계 진행
planner/solver.py         안정성 고려 EDF 스케줄러, 계획 diff
planner/feasibility.py    마감별 용량 분석, 검증된 대안 생성
planner/ops.py            LLM이 호출하는 연산 + 검증·안전 규칙
planner/agent.py          함수 호출 프롬프트, 날짜표 그라운딩, 근거 기반 설명
planner/safety.py         모더레이션, 위기 대응, 과로 감지, 제목 정제
planner/calendar_source.py Google Calendar(읽기 전용) / 샘플 캘린더
eval/                     시나리오 생성, 체커, 베이스라인, 평가 실행
ASSIGNMENT.md             과제 안내 원문
```
